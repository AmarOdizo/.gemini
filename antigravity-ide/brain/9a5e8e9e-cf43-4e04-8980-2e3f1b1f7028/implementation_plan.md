# Database Architecture Refactoring: Migrate to Separate Collections

This plan details the process of removing the single-table Master Data Store (`DataStore.js` with discriminator patterns) and replacing it with distinct, standard MongoDB collections for each module in the `gemini/API` backend.

## User Review Required

> [!WARNING]
> This is a destructive operation regarding the existing `master_data` collection structure. The new architecture will create new collections (e.g., `users`, `pets`, `vets`, `appointments`, etc.). The existing data in `master_data` will no longer be queried by the application unless manually migrated. However, the provided seed scripts will repopulate the new collections instantly.
> 
> Please review and approve this plan.

We will completely remove the discriminator pattern. Each model will be converted to use the standard `mongoose.model()` structure, creating independent collections.

### Seeding Scripts & Routes

With the `DataStore` gone, any central database clearing functions (like `DataStore.deleteMany({})`) must be updated to explicitly target all independent collections to prevent data accumulation during reseeding.

#### [MODIFY] [`seed_full_database.js`](file:///c:/Users/VICTUS/.gemini/API/seed_full_database.js)
- Remove `const DataStore = require("./models/DataStore");`
- Replace `DataStore.deleteMany({})` with individual cascading deletions:
  ```javascript
  await Promise.all([
      User.deleteMany({}), Pet.deleteMany({}), Vet.deleteMany({}),
      Appointment.deleteMany({}), Consultation.deleteMany({}), 
      Prescription.deleteMany({}), ChatMessage.deleteMany({})
  ]);
  ```

#### [MODIFY] [`apiRoutes.js`](file:///c:/Users/VICTUS/.gemini/API/routes/apiRoutes.js)
- Update the `/api/seed` route similarly. Remove the `DataStore` import and clear all separate collections concurrently before reseeding.
